1. Executive Summary & Objective

Virtual clothing try-on presents a fundamental machine learning challenge: synthesizing a photorealistic, wrinkle-aware, and drape-consistent garment onto a target human image while strictly preserving the subject's identity (face, hairstyle, pose, body proportions, hands) and the surrounding scene.

This project transitions raw research-grade diffusion models into a production-ready, reproducible, and monitorable MLOps architecture. By decoupling heavy GPU tensor computing into an isolated node-based engine (ComfyUI) and orchestrating data validation, execution, experiment tracking, and client serving through ZenML, MLflow, and FastAPI, the system achieves sub-25-second inference with zero memory leakage and rigorous pipeline governance.

Key Innovation: Unlike traditional text-guided diffusion models that attempt to inject cloth appearance via Cross-Attention layers (frequently resulting in lost garment textures, blurry logos, and bleeding artifacts), CatVTON concatenates the target person, reference garment, and body-agnostic mask directly along the spatial and channel dimensions. This maintains high spatial fidelity and precise garment boundary alignment.

3. Comprehensive Breakdown of Implemented Steps

Every stage of the pipeline fulfills a distinct responsibility with strictly defined input and output contracts.

1 Data Versioning & Benchmark Baseline
data.dvc | manifests/benchmark_dataset.json

Generative image models are highly sensitive to dataset corruption, subtle resolution changes, and missing reference pairs. To ensure absolute data reproducibility without storing gigabytes of binary image data inside Git:

  • DVC Tracking: The data/benchmark/ directory (containing standard benchmark pairs person_1.jpg and garment_1.jpg) is tracked via content-hash pointers in data.dvc.
  • Manifest Metadata: manifests/benchmark_dataset.json defines the schema version, ground-truth image dimensions, and sample identifiers for reproducible evaluation runs.
Inter-Step Relation: Feeds baseline validation pairs into Step 5 (ZenML Pipeline) and Step 8 (Standalone Baseline Runs) ensuring test coverage can be validated deterministically.
2 Garment Classification & Dynamic Masking
src/preprocessing/classifier.py

Virtual try-on requires an agnostic mask: a binary mask that eliminates existing garments from the person's image while preserving the face, skin, arms, hands, neck, and background.

  • Category Detection: Inspects the incoming garment image geometry and aspect ratio (e.g. aspect ratio ≥ 1.6 indicates full-body dress/jumpsuit; 1.0–1.3 indicates upper-body shirts/jackets).
  • Dynamic Boolean Flags: Configures 35+ discrete boolean flags for the downstream human parser:
    • Upper Body: shirt=True, top=True, sweater=True, collar=True, sleeve=True, pants=False
    • Lower Body: pants=True, shorts=True, skirt=True, belt=True, shirt=False
    • Full Body: dress=True, jumpsuit=True, shirt=True, skirt=True
Inter-Step Relation: The output flag dictionary is dynamically injected into Node 5 (FashionClothMask) in Step 4, dictating exactly where the diffusion inpainter is permitted to generate pixels.
3 Core Generative Model — CatVTON
src/models/CatVTON/model/pipeline.py

The core visual generation engine is CatVTON (Concatenation-based Virtual Try-On):

  • Base Diffusion Backbone: Built upon runwayml/stable-diffusion-inpainting and enhanced with the stabilityai/sd-vae-ft-mse Autoencoder for crisp, artifact-free image decoding.
  • Skip Cross-Attention: Traditional text cross-attention is replaced with SkipAttnProcessor. The model instead receives the target person, the reference garment, and the agnostic mask concatenated directly in the latent representation.
  • Checkpoint Version ("mix"): Uses the official zhengchong/CatVTON mixed checkpoint (mix-48k-1024), trained across both the VITON-HD (upper body) and DressCode (dresses, skirts, pants) datasets at full 1024×768 resolution.
  • Inference Sampling: DDIM scheduler operating at CFG = 2.5 over 25–40 steps.
Inter-Step Relation: Executes the core latent diffusion math within Step 4 (ComfyUI Node 3) or standalone in Step 8, transforming inputs from Steps 1 & 2 into a photorealistic synthesized human subject.
4 Decoupled GPU Engine & Node Graph Workflow
workflow_api.json | ComfyUI (:8188)

Running multi-gigabyte PyTorch models directly inside a multi-threaded web API worker inevitably leads to CUDA out-of-memory errors and request blocking. The pipeline decouples inference into ComfyUI:

  • Node 1 (LoadImage): Loads the staged person image from disk.
  • Node 2 (LoadImage): Loads the staged garment image.
  • Node 5 (FashionClothMask): Combines Self-Correction Human Parsing (SCHP) and DensePose body mapping to segment the person using the dynamic category flags from Step 2.
  • Node 3 (CatVTONNode): Applies mask dilation (mask_grow=25) to eliminate boundary seams, ingests Nodes 1, 2, and 5, and executes the reverse diffusion process.
  • Node 4 (SaveImage): Saves the generated PNG to ~/ComfyUI/output/.
Inter-Step Relation: Managed asynchronously by FastAPI (Step 7) and ZenML (Step 5) via HTTP REST calls (/prompt to dispatch, /history/{id} to poll).
5 MLOps Pipeline Orchestration
pipeline.py (ZenML)

ZenML orchestrates the end-to-end execution of the try-on workflow, providing standardized pipelines and artifact lineage:

  • @step virtual_tryon_step: Ingests the image filenames, verifies workflow blueprint integrity, dispatches the prompt to ComfyUI, polls for completion, measures latency, and handles artifact copying.
  • @pipeline virtual_tryon_pipeline: Chains steps and enforces enable_cache=False. Because diffusion generation produces novel pixels per request, caching must be bypassed to avoid returning stale images.
Inter-Step Relation: Bridges ComfyUI execution (Step 4) with MLflow experiment tracking (Step 6), standardizing pipeline runs for automated CI/CD and future Kubernetes deployments.
6 Experiment Tracking & Model Lineage
mlflow.db | mlartifacts/ | start_mlflow.sh

Centralized tracking server operating on an embedded SQLite database (mlflow.db) with artifact proxy storage (mlartifacts/):

  • Hyperparameter Logging: Automatically logs model_architecture, person_image, garment_image, steps, cfg, seed, and compute device.
  • Metric Logging: Tracks inference_latency_seconds and pipeline_success flag (1.0 or 0.0).
  • Artifact Registry: Every rendered image is committed to the MLflow artifact repository under its immutable run_id.
Inter-Step Relation: Records operational metrics generated during Step 5 and Step 8, enabling full auditability, quality regression detection, and performance tracking over time.
7 Production REST API Gateway & Serving
main.py (FastAPI)

A commercial-grade asynchronous web service providing robust endpoints for end-users and e-commerce integrations:

  • POST /api/v1/try-on: Accepts multipart uploads, performs input validation, invokes the garment classifier (Step 2), patches the ComfyUI blueprint (Step 4), polls the job, saves local outputs, and formats the response (as JSON with base64 image data or raw streaming PNG).
  • POST /api/v1/classify-garment: Standalone garment classification endpoint returning detected category and mask flags.
  • GET /api/v1/analytics: Real-time telemetry reporting total requests, successful renders, average latency, and success rate.
  • GET /health: System health and ComfyUI engine reachability probe.
Inter-Step Relation: The central operational hub that interfaces with clients, triggering Steps 2, 4, 5, and delivering synthesized results back to the caller.
8 Standalone Baseline & Comprehensive Test Suite
src/models/run_*.py | tests/

Provides decoupled execution scripts and automated quality assurance:

  • Automatic Hardware Adaptation: run_baseline.py, run_reproducible.py, and run_mlflow.py dynamically detect GPU availability—using CUDA with bfloat16 when an NVIDIA GPU is present, and gracefully falling back to CPU with float32.
  • Pytest Suite: Comprehensive tests validating API response contracts (test_api.py), DVC data integrity (test_dvc.py), MLflow schema and runs (test_mlflow_zenml.py), and live end-to-end inference.
Inter-Step Relation: Acts as the continuous verification harness for the entire repository, guaranteeing that changes to weights, schemas, or dependencies never break production.
